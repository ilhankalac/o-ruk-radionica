Plan radionica — Rožaje web sajt projekat

11 radionica × 2h  •  ~6 vikenda  •  15 srednjoškolaca · 4 tima  •  HTML · CSS · JavaScript · AI · Git

Format: 11 radionica × 2h (zadnji vikend ima 1 radionicu). Učenici: 15 srednjoškolaca (15–18 god), bez prethodnog znanja. Timovi: 4 tima po 3–4 člana, svaki ima lidera. Solo instruktor.

Promjene u odnosu na prvobitni plan: (1) stara R2 (HTML skelet) i stara R3 (više stranica + navigacija) spojene su u jednu radionicu (R2) → ukupno 11 radionica umjesto 12. (2) Git je podijeljen na dvije radionice (R5 osnove, R6 branch + Pull Request), AI sveden na jednu (R7), a R8–R10 su timski projekat sa GitHub PR workflow-om (instruktor review-uje i merge-uje PR-ove). R11 ostaje posvećena finalnoj prezentaciji.

Ključne strateške odluke

Git pristup (dvije radionice): NE na početku. Prve 4 radionice rade na "lead laptopu" tima + USB backup + Google Drive folder. GitHub Desktop (GUI) uvodi se u R5 kao "cloud backup" (commit/push/pull, repo po timu), tek kad osjete "izgubio sam fajl" bol. U R6 nadograđuje se na branch + Pull Request — workflow koji koriste cijelu projektnu fazu: svaki član radi na svom branch-u, otvara PR, a instruktor je reviewer koji pregleda i merge-uje. Terminal se NIKAD ne koristi — sve kroz GitHub Desktop + GitHub web.

Deploy: Netlify Drop umjesto GitHub Pages (drag & drop, URL za 15 sekundi, bez Git-a). GitHub Pages kao bonus za brže timove.

Editor: VS Code lokalno + Live Server ekstenzija. R1 posveti 20 min samo na setup — vrijedi ulaganja.

Template strategija: Svi timovi dobijaju isti skelet sajta (5 stranica: Početna, Atrakcije, Smještaj, Hrana, Kontakt). Razlikuju se sadržajem, bojama, fotografijama, "wow" detaljima. Debug-uješ jednu strukturu — ogromna ušteda vremena za solo instruktora.

Team workflow evolucija:

  • R1: Svi rade na svom laptopu, grade istu stvar (čisto učenje).
  • R2–R4: Svaki član tima postaje "vlasnik" jedne stranice, lider integriše ručno.
  • R5: Lični sajt + beleške na lični GitHub (portfolio) preko GitHub Desktop.
  • R6: Timski "Visit Rožaje" repo. Svaki član svoj branch → Pull Request → instruktor review/merge. Tu se vježba workflow.
  • R8–R10: Pun timski rad preko PR-ova; ti pratiš sve na GitHub-u, ostavljaš komentare i merge-uješ u main.

Pravilo rotacije kucanja: Na svakih 15 min mijenja se ko tipka u timu. Ti držiš štopericu.

RADIONICA 1 — "Kako internet radi i prvi sajt" ODRAĐENO · 17. maj

Cilj: Demistifikovati web. Do kraja radionice svaki učenik ima index.html koji otvara u browseru.

Šta je stvarno odrađeno: kako web radi (klijent traži request → server vraća response), čitanje Network taba, podizanje lokalnog servera kroz Live Server ekstenziju, prvi HTML tagovi (<h1>, <p>, <img>). Bonus: priča o učenju (Sistem 1 / Sistem 2 razmišljanje) — normalno je da je teško na početku.

Sadržaj:

  • 0:00–0:15 — Dobrodošlica, najava tima i nagrade (domen + sertifikati). Pokaži 2-3 inspirativna tourism sajta (ne AirBnB, nego manje sajtove koji izgledaju dostižno).
  • 0:15–0:35 — "Šta se desi kad otkucaš google.com?" — jednostavna priča: browser traži fajl od servera, server pošalje fajl, browser ga prikaže. Bez detalja.
  • 0:35–0:50 — SETUP: VS Code + Live Server ekstenzija. Ovdje će biti haosa — vidi pitfall sekciju.
  • 0:50–1:00 — PAUZA.
  • 1:00–1:30 — Prvi fajl: index.html. Uči <h1>, <p>, <img>. Svako piše "Zdravo, ja sam X iz tima Y, gradimo sajt o Rožajama."
  • 1:30–1:55 — Zadatak: dodati sliku Rožaja (bilo koja sa Googla), naslov, i 3 pasusa o tome zašto vam se sviđa grad.
  • 1:55–2:00 — Show & tell.

Domaći: Donijeti 5 fotografija Rožaja sa telefona ili interneta.

RADIONICA 2 — "HTML skelet + više stranica i navigacija" ODRAĐENO · 23. maj

Cilj: Razumjeti HTML kao strukturu (nije stil) i povezati stranice u "pravi" multi-page sajt.

Spojene radionice: ovdje su objedinjene stara R2 (HTML skelet) i stara R3 (više stranica + navigacija). Stvarno odrađeno: glavni tagovi (<header>, <main>, <section>, <footer>, <ul>/<ol>/<li>, <nav>), naslovi/hijerarhija, linkovi (<a>) — eksterni (https://...) i lokalni (ime-fajla.html) — i klikanje kroz povezane stranice lokalno.

Sadržaj:

  • 0:00–0:10 — Review: šta je HTML tag?
  • 0:10–0:40 — Glavni tagovi: <header>, <main>, <section>, <footer>, <ul><li>. Analogija: HTML = skelet kuće, CSS = boja i namještaj (sljedeće).
  • 0:40–1:00 — Vježba: svi grade istu strukturu početne strane (header + 3 sekcije + footer).
  • 1:00–1:10 — PAUZA.
  • 1:10–1:35 — Linkovi: <a href="...">. Razlika eksterni link (https://...) vs. lokalni link na vlastiti fajl (best-film.html). Folder struktura + <nav> sa istim linkovima na svakoj stranici.
  • 1:35–1:50 — Timski izbor: ime sajta, slogan, glavne boje (samo dogovor, ne kodiranje). Popunjavaju početnu stvarnim sadržajem.
  • 1:50–2:00 — Show & tell: tim klika kroz povezane stranice.
Pitfall: relativne putanje (slike/foto.jpg vs /slike/foto.jpg) i tipfeleri u href (case-sensitive: Best-film.html ≠ best-film.html). Unaprijed demonstriraj tačan način.

Domaći: Nema. Odmor.

RADIONICA 3 — "CSS — boje i tipografija" ODRAĐENO · 24. maj

Cilj: Sajt prestaje izgledati kao iz 1995. Prvi pravi "wow" moment.

Stvarno odrađeno: tri načina pisanja CSS-a (inline / internal / external), <link rel="stylesheet">, element vs. class selektor, color, background-color, font-family, font-size, padding, margin, border, max-width, hex boje sa coolors.co, Google Fonts (Poppins). Bonus koji nije bio u prvobitnom planu: CSS Box Model (content → padding → border → margin).

Sadržaj:

  • 0:00–0:10 — Demo: isti HTML, različit CSS = potpuno drugačiji izgled. Pokaži 2-3 primjera.
  • 0:10–0:30 — <link> na style.css. Selektori: element, klasa. Property-ji: color, background-color, font-family, font-size.
  • 0:30–0:55 — Vježba: svi prave istu stilizaciju (plavi header, bijela slova, itd.) da svi vide da rade isto. Box model uživo kroz DevTools.
  • 0:55–1:05 — PAUZA.
  • 1:05–1:30 — Timska paleta: svaki tim bira paletu boja (imaj otvorene 3-4 palete na coolors.co unaprijed).
  • 1:30–1:55 — Primjenjuju paletu. Google Fonts — 1 font po timu.
  • 1:55–2:00 — Show & tell.

RADIONICA 4 — "CSS Layout — kartice i rasporedi" ODRAĐENO · 31. maj

Cilj: Sajt izgleda kao pravi sajt, ne kao Word dokument.

Stvarno odrađeno: Flexbox sa 4 propertyja na container-u (display: flex, gap, flex-wrap, justify-content), tri varijante justify-content (space-between / center / end), kartice (border-radius, border, padding) i slike (width: 100%, fiksna height, object-fit: cover).

Sadržaj:

  • 0:00–0:15 — Review. Demo layout-a: kartice u redovima (kao Airbnb listing).
  • 0:15–0:45 — Flexbox — SAMO 4 property-ja: display: flex, gap, justify-content, flex-wrap. NE ulazi dalje (bez align-items, flex-grow, itd.).
  • 0:45–1:00 — Vježba: svi prave red od 3 "kartice atrakcije" (slika, naslov, tekst).
  • 1:00–1:10 — PAUZA.
  • 1:10–1:50 — Timovi primjenjuju flexbox na stranici Atrakcije i Hrana. Lider + vlasnik stranice rade zajedno.
  • 1:50–2:00 — Show & tell. Ovdje prvi put reći će "ohoho, izgleda kao pravi sajt" — iskoristi taj trenutak.

Domaći: Razmisliti u timu šta je "glavna atrakcija" (theme) njihovog sajta — oko čega se gradi priča.

RADIONICA 5 — "Git deo 1: GitHub Desktop i cloud backup" SLIJEDI

Cilj: Razumjeti Git kao "dugme za backup u cloud", ne kao sistem verzionisanja. Svaki učenik pushuje lični sajt na lični GitHub (portfolio).

Sadržaj:

  • 0:00–0:15 — Priča: "Zamislite da se laptop pokvari noć prije prezentacije. Gdje je sajt? Nigdje. Danas rješavamo to."
  • 0:15–0:35 — Kreiranje GitHub naloga (ako nemaju). Instalacija GitHub Desktop.
  • 0:35–0:55 — SAMO tri dugmeta: Commit ("sačuvaj snimak"), Push ("pošalji u cloud"), Pull ("skini najnoviju"). Danas ne spominji branch/PR — to je sljedeći put.
  • 0:55–1:05 — PAUZA.
  • 1:05–1:45 — Svako napravi lični repo i pushuje svoj lični sajt + beleške → lični GitHub profil (portfolio). Ovo zatvara Fazu 1.
  • 1:45–2:00 — Vježba + show & tell: napravi malu izmjenu → commit → push → osvježi GitHub u browseru → "vidiš, u cloud-u je".
Analogija koju ponavljaš: "Git je cloud backup. Šta ako ti laptop nestane? Git te čuva." Bez priče o verzionisanju.

RADIONICA 6 — "Git deo 2: branch + Pull Request (timski repo)" SLIJEDI

Cilj: Postaviti timski "Visit Rožaje" repo i naučiti workflow koji koriste cijelu projektnu fazu — svako na svom branch-u, PR ide instruktoru na pregled.

Pristup: "kuvarski", isto kao JS. Ne objašnjavaš Git iznutra — objašnjavaš šta koje dugme uradi i zašto. Sve kroz GitHub Desktop + GitHub web, nikad terminal.

Sadržaj:

  • 0:00–0:15 — Review tri dugmeta iz R5. Problem koji rješavamo: "4 osobe u timu diraju isti sajt — kako da se ne pogaze?"
  • 0:15–0:35 — Lider pravi timski repo "Visit Rožaje", ostali dobijaju pristup (collaborators) i cloniraju.
  • 0:35–0:55 — Branch = "tvoja kopija sajta da ne razbiješ glavni dok radiš". Svaki član pravi svoj branch (npr. marko-atrakcije) u GitHub Desktop.
  • 0:55–1:05 — PAUZA.
  • 1:05–1:40 — Pull Request = "molba: pregledaj moj rad i ubaci ga u glavni sajt". Svako napravi malu izmjenu → commit → push branch → otvori PR na GitHub-u. Ti si reviewer: na projektoru pokažeš kako otvaraš PR, ostaviš komentar, klikneš Merge.
  • 1:40–1:55 — Svi urade Pull na main → vide da je tuđa izmjena ušla. "Ovako ćemo raditi cijeli projekat."
  • 1:55–2:00 — Show & tell.
Pitfall — konflikti: svedeni na minimum jer svako radi na svojoj stranici / svom branch-u. Pravilo: jedan fajl = jedan vlasnik. Merge konflikt rješavaš ti u PR-u, ne oni. Drži PR-ove male i česte.

RADIONICA 7 — "AI kao pomoćnik — etika, halucinacije, sadržaj" SLIJEDI

Cilj: Demistifikovati AI (alat, ne magija), naučiti šta je halucinacija, i generisati provjeren sadržaj za timski sajt. Možda najvažnija radionica kursa.

Sadržaj:

  • 0:00–0:25 — Otvoreni razgovor: Ko koristi ChatGPT? Za šta? Uživo pokaži halucinaciju — pitaj AI o izmišljenoj rožajskoj atrakciji ili "najstarijem restoranu u Rožajama od 1750." Vidjećeš kako izmisli. Neprocjenjiva lekcija.
  • 0:25–0:45 — Osnove dobrog prompta: kontekst, cilj, format, ograničenja. Primjer: "Napiši kratak pasus (80–100 riječi) o Hajli za turistički sajt o Rožajama. Ton pozivan ali činjeničan. Ne izmišljaj brojeve ili datume. Ako nešto ne znaš, napiši 'PROVJERI'."
  • 0:45–1:00 — Bonus: AI za dizajn savjete ("predloži paletu za planinski turizam", "koji font za tradicionalnu kuhinju"). Timovi isprobavaju.
  • 1:00–1:10 — PAUZA.
  • 1:10–1:50 — Timovi koriste Claude (4 naloga) za tekstove svog sajta. Zlatno pravilo: sve što AI napiše MORA se provjeriti (makar Wikipedia) prije ubacivanja.
  • 1:50–2:00 — Diskusija: Šta je AI izmislio? Šta je tačno?

Domaći: Svaki tim vodi "AI dnevnik" — šta su pitali, šta su dobili, šta su provjerili. Koristiće na finalnoj prezentaciji.

RADIONICA 8–10 — "Timski projekat: Visit Rožaje" SLIJEDI · 3 radionice

Cilj: Timovi uzimaju najbolje ideje iz ličnih sajtova i grade zajednički "Visit Rožaje" sajt. Sav rad ide kroz branch → Pull Request → tvoj review/merge (workflow iz R6).

Format: sve tri radionice prate isti šablon — kratka just-in-time mini-lekcija (10–20 min) na vrhu, ostatak je timski rad dok ti pratiš PR-ove na GitHub-u i trčiš između timova. Nove teme (JS, responsive, deploy, CSS polish) utkane su tu — uvodiš ih kad je tim spreman, ne kao posebne radionice.

Stalna struktura svake od tri radionice

  • 0:00–0:10 — Review: koji PR-ovi su mergeani od prošlog puta, šta je na redu danas (kratak demo/cilj).
  • 0:10–0:30 — Mini-lekcija po potrebi (vidi "teme koje utkavaš").
  • 0:30–1:00 — Timski rad: svako na svom branch-u, otvaraju PR-ove.
  • 1:00–1:10 — PAUZA.
  • 1:10–1:50 — Nastavak rada; ti uživo review-uješ PR-ove na projektoru (kratak komentar + merge) da svi vide kako izgleda pregled koda.
  • 1:50–2:00 — Show & tell: svaki tim pokazuje šta je mergeano danas.

Teme koje utkavaš kroz R8–R10 (kad je tim spreman)

  • JS feature (1 po timu, "kuvarski"): hamburger meni / slideshow / "pokaži više" dugme. Pravilo "20 linija ili manje". Objašnjavaš linijama, ne konceptima. → wow: "sajt se pomjera".
  • Responsive: <meta viewport> + JEDAN media query @media (max-width: 768px). Poprave tri stvari: font-size, flex-wrap, manji padding. Testiraju na svom telefonu. → wow: "pokaži mami".
  • CSS polish: box-shadow, border-radius, hover efekti. Samo ova tri.
  • Deploy (najkasnije u R10): Netlify Drop — drag & drop folder → URL za 15 sekundi. Bonus za jače timove: GitHub Pages iz repo-a. → wow: "stvarno je na internetu".

Naglasci po radionici (orijentaciono, ne kruto)

  • R8 — start: postaviti timski sajt iz najboljih ideja, podjela stranica, prvi PR-ovi prolaze. Uvedeš JS feature ako tim već ima strukturu.
  • R9 — nastavak: sadržaj (AI tekstovi iz R7) + responsive + CSS polish. Više PR-ova, ti review-uješ.
  • R10 — zatvaranje: deploy (sajt online), "bug hunt" (timovi traže greške jedni drugima), feature freeze — od kraja R10 samo bug-fix, ne novi features. Vježba prezentacije (1 min po timu). Domaći: 3-minutna prezentacija.

RADIONICA 11 — "Finalne prezentacije i dodjela" SLIJEDI

Cilj: Zatvaranje, ponos, javnost. Pozovi roditelje, direktora škole, možda lokalne novine.

Sadržaj:

  • 0:00–0:15 — Okupljanje, dobrodošlica gostima.
  • 0:15–1:15 — Prezentacije: svaki tim 10–12 min (3 min prezentacija + 2 min pitanja + show na projektoru, × 4 tima).
  • 1:15–1:30 — PAUZA + grickalice.
  • 1:30–1:50 — Dodjela: sertifikati za sve, domen za pobjednički tim. Više kategorija (Najbolji dizajn / Najbolji sadržaj / Najbolji timski duh / "Wow" faktor) — niko ne smije otići bez priznanja.
  • 1:50–2:00 — Grupna fotografija ispred projektora sa svim sajtovima.

Česte zamke (pitfalls) i kako ih izbjeći

  1. Setup haos na R1. Stari laptop, nema admin prava, pogrešna verzija Windows-a. → Zahtijevaj da dođu 15 min ranije sa instaliranim VS Code-om. Pošalji uputstvo dan prije. Imaj rezervni USB sa offline installerom.
  2. "Meni ne radi!" — U 80% slučajeva: nezatvoren tag, fajl je index.html.txt, sačuvali u pogrešan folder. → Nauči ih VS Code auto-format (Shift+Alt+F) od R1. Windows: pokaži "Show file extensions" odmah.
  3. "Izgubio sam fajl." Prije R5 — stvarno se dešava. → Pravilo: svaka radionica završava sa kopijom foldera na USB ili Google Drive. Lider tima odgovoran.
  4. Kopiranje AI koda bez razumijevanja. Slome sajt ubacivanjem koda koji ne shvataju. → Od R6 pravilo: "Ako koristite AI kod, lider mora objasniti svaki red PRIJE ubacivanja."
  5. Jedan tinejdžer monopolizuje laptop. → Pravilo rotacije — na svakih 15 min mijenja se ko kuca. Ti kontroliraš štopericu.
  6. Timska drama. Sa 15 tinejdžera — očekuj bar jedan konflikt. → Ne miješaj se osim ako ne blokira rad. Imaj "back-up" aktivnost (npr. "idi napravi logo u Canva-i").
  7. Preambiciozni timovi. Hoće videos, animacije, slome sajt dan prije prezentacije. → "Feature freeze" od R10. Poslije R9 — samo bug-fix, ne novi features.
  8. "Dosadno mi, sve znam." → Pripremi bonus zadatke (Leaflet mapa, forma kontakta preko Formspree, dark mode toggle). Ne drži ih na nivou grupe.
  9. Wi-Fi kolaps. 15 laptopa + telefona na jednom ruteru = problemi. → Testiraj prostoriju prije. Imaj offline backup svih resursa na USB-u.
  10. Copy-paste slika iz Googla. → Pokaži im desni klik → Save image as u folder sajta, i razliku između .jpg i .png.

Motivacioni trikovi

  1. "Wow" momenti unaprijed isplanirani. Svaka radionica mora imati jedan "ohoho" trenutak:
    • R1: "Otvaram SVOJU stranicu u browseru!"
    • R3: Prve boje + fontovi = "liči na pravi sajt"
    • R4: Flexbox kartice = "izgleda kao Airbnb"
    • R5: Lični sajt na GitHub-u = "moj sajt je u cloud-u"
    • R6: Prvi PR mergean = "moj kod je ušao u glavni sajt"
    • R8–R10: JS feature = "sajt se pomjera" · telefon = "pokaži mami!" · URL = "stvarno je na internetu"
  2. Plakat napretka u učionici. 11 kvadratića na zidu. Svaki vikend "pečatiraš" odrađene kvadratiće. Djetinjasto, ali radi.
  3. Nazovi ih "programerima" od R1. Jezik oblikuje identitet. "Programeri, danas gradimo..."
  4. Podsjetnik koliko su napredovali. Kraj svake radionice — 30 sekundi: "Danas smo napisali 40 linija koda. Prije par nedjelja, ovo vam je bilo nečitljivo."
  5. "Feature showcase" između timova. Svaki vikend jedan tim pokaže nešto što su otkrili, ostali mogu kopirati.
  6. "Hroničar" uloga. Jedan član tima (ne lider) slika ekrane, bilježi zanimljive greške. Ide u finalnu prezentaciju.
  7. Lična priča o gradu. "Moja baka pravi najbolje pite u mahali", "sa dedom sam išao na Hajlu kad sam bio mali". Pretvara školski zadatak u ličnu stvar.
  8. Sitni ritual na početku. Svaka radionica kreće sa istom rečenicom ili šalom. Stabilnost smanjuje anksioznost.

"Wow" feature ideje (bonus za brže timove)

Lake (1 radionica): Galerija slika sa lightbox efektom (CSS-only, copy-paste) · Animirana mapa Rožaja sa Leaflet.js (10 linija koda) · Dark mode toggle · Forma kontakta preko Formspree (bez backend-a) · Vremenska prognoza za Rožaje (OpenWeather API embed).

Srednje (2 radionice): Filter atrakcija po kategoriji (planina / grad / restoran) · Google Maps embed sa označenim atrakcijama · "Događaji" stranica sa listom manifestacija.

Impresivno za prezentaciju: Mini-kviz o Rožajama (5 pitanja, JS + rezultat) · Virtuelna šetnja (360° fotografija) · Audio pozadinska muzika (sa mute dugmetom, obavezno!) · Timeline istorije Rožaja (CSS scroll efekat).

Kako predstaviti JavaScript bez preopterećenja

Najdelikatniji dio kursa — strategija u 5 koraka (R8):

  1. Ne koristi riječ "programiranje" za JS posebno. Oni već "programiraju" od R1 (HTML i CSS su njihov kod). JS je samo "kod koji se dešava kad se nešto desi."
  2. Nijedan koncept nije apstraktan — sve preko primjera. Ne: "varijabla je kontejner za vrijednost." Jeste: "document.querySelector('.menu') znači 'nađi ono što ima klasu menu'."
  3. Prvi JS je uvijek interakcija sa dugmetom. Dugme + alert ili dugme + promjena klase. Vizuelni efekat odmah.
  4. Pravilo "20 linija ili manje". Ako feature prelazi 20 linija JS-a, prekompleksno je. Skrati ili izbaci.
  5. Nikad ne objašnjavaj JavaScript teoriju "unaprijed". Ideš direktno u primjer, objašnjavaš linije kako koriste.

Kako predstaviti Git jednostavno (dvije faze)

Git je najveća zamka za početnike. Dijelimo ga na dvije radionice — prvo backup (R5), pa tek onda saradnja (R6).

Opšta pravila (oba puta):

  1. Ne predstavljaj Git na R1. Oni prvo moraju osjetiti bol "izgubio sam fajl". Pustiti ih 4 radionice da to osjete.
  2. Koristi GitHub Desktop + GitHub web, NE terminal. Nikada. Terminal dolazi 5 godina kasnije u životu.
  3. "Kuvarski" pristup. Ne objašnjavaš Git iznutra — objašnjavaš šta koje dugme uradi i zašto ti treba.

R5 — tri dugmeta (backup): Commit = "sačuvaj snimak" · Push = "pošalji u cloud" · Pull = "skini najnoviju". Analogija: Git je cloud backup, ne verzionisanje. Lični repo po učeniku (portfolio).

R6 — branch + Pull Request (saradnja):

  1. Branch = "tvoja kopija da ne razbiješ glavni sajt dok radiš". Jedan član = jedan branch = jedna stranica/feature.
  2. Pull Request = "molba da se moj rad ubaci u glavni sajt; neko ga pregleda prije nego uđe".
  3. Instruktor je reviewer. Ti otvaraš/pregledaš PR-ove, ostavljaš komentar i klikneš Merge. Učenici prave PR-ove; merge i bilo kakav konflikt ide preko tebe.
  4. Jedan timski repozitorij (ne po članu). Pravilo "jedan fajl = jedan vlasnik" drži konflikte na minimumu. Drži PR-ove male i česte.
  5. I dalje NE: rebase, force-push, složeno grananje. Samo: branch → commit → push → PR → merge.

Pred R1 — checklist za instruktora

  • Poslati uputstvo za instalaciju VS Code-a (Windows) — dan prije R1
  • Pripremiti 3–4 "inspirativna" manja tourism sajta kao primjere
  • Pripremiti skelet sajta (5 HTML fajlova sa placeholder-ima) — najveća investicija unaprijed
  • Pripremiti 4–5 paleta boja na coolors.co (otvoreni tabovi za R3)
  • Kreirati 4 Claude naloga (za R7)
  • Pribaviti domen rezervaciju (za nagradu pobjedničkom timu)
  • Dizajnirati sertifikate (Canva, 15 min)
  • Potvrditi projektor/TV u prostoriji svaki vikend
  • Testirati Wi-Fi sa više uređaja istovremeno
  • Pripremiti USB sa offline installerom VS Code-a
  • Pripremiti folder "resursi" na USB-u sa 30+ slika Rožaja
  • Timska podjela (procjena nastavnika + lično poznanstvo)
  • Pozvati goste (roditelje, direktora, lokalne novine) za R11 — 3 nedjelje unaprijed

Ključni principi kroz cijeli kurs

  1. Nikada ne piši kod koji oni ne razumiju. Ako ne mogu objasniti šta linija radi, obriši i idi sporije.
  2. Kodiraj uživo pred njima. Praviš grešku pred njima, pokazuješ kako je tražiš, popravljaš. Magija je proces debugovanja.
  3. Svaka radionica = funkcionalni sajt na kraju. Nikada ne ostavljaj "polomljen" sajt za sljedeću radionicu.
  4. Slavi svaku pobjedu javno. Mala pohvala pred grupom = najveća motivacija.
  5. AI je alat, ne autor. Zlatno pravilo do R11: "Ako ne možeš objasniti, ne možeš koristiti."
  6. Oni su programeri. Ne "učenici koji uče programiranje." Jezik oblikuje identitet.
